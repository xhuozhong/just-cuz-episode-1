# 第一集公开版验收说明

本版包含34页、38个已验收主格及50个可独立操作的交互区域。

独立文件审核确认：

- 6437张运动缓存帧由JPEG转为WebP，逐帧来源、顺序和尺寸均已核对，没有增删帧、插帧或合成新视角。
- 当前运动缓存直接由保留JPEG编码为WebP q76（原q84更小时保留原缓存），不宣称无损或与原JPEG逐像素相同。
- 34张完整原页、38张分格原图、38个MP4及38张文字保护层均保持已验收文件的原始字节与SHA-256；文字保护层未重新绘制。
- 公开播放器实际接受全部38组WebP序列，保留50个独立区域。公开资源清单经过脱敏与文件完整性核对。

实际浏览器检查还包括第13阅读页子视图独立拖动、惯性及复位，390px窄屏第18阅读页双格重新抓取后立即停止，以及源第008页惊讶场景拖动时邻近场景保持不动。文件审核与浏览器操作分别记录。

公开网络的冷加载检查发现并修复了一个恢复问题：视频或文字保护层加载超过15秒时保留原画并继续等待，资源随后完成解码及尺寸校验后自动恢复互动。真正的加载错误、尺寸不符和不支持的保护层仍会阻止互动，不会展示未经保护的画面。该修复未改动任何原画、运动帧、视频、保护层或音乐文件。

首次互动的加载方式随后进行了调整：6437张既有WebP原字节被分装为152个带SHA-256与索引的交错帧包，38组各4包，保持来源绑定、帧数、顺序及每帧内容。解析器核对包SHA、长度、索引覆盖及实际解码尺寸。后续流式版本在配置中绑定每帧长度与SHA-256；完整索引表通过检查后，各帧须独立验证再显示，包尾继续检查整包SHA。已逐帧验证的画面无需等待包尾即可互动；尚未验证或受损帧不能显示。包内传输顺序优先原视角左右相邻方向，时间轴的原帧索引不变。缓存帧与真实文字保护层就绪即可互动，MP4作为按需后备，仍须通过实际尺寸、时长、解码与定位范围检查。页头采用文字提示准备状态，不添加进度条。

本轮测试覆盖缓存主路径在MP4尚未加载时的拖动、原画复位、邻格独立、迟到资源、错误包与视频后备，以及状态提示与真正可拖动状态一致。打包工具另逐帧还原对比全部6437张原WebP，原画、视频、保护层和音乐未重新编码。

本说明汇总已完成的文件审核和代表性界面测试，不把帧数当作独立视角数量，也不宣称所有视频均为无剪接、几何标定的完整360°轨道。

公开网络抽样中，旧式整包读取2.50 MB耗时约51.7秒；这是单次样本，不代表固定加载时间。公开浏览器已验证缓存全部到达后按键能从第0帧切换到第3帧，而MP4仍未加载。流式版本的冷加载表现须另外以实际公开页面核验，不由文件检查或模拟测试推断。

当前页加载优化：完整frame-sequences.json保留作离线审计，网页不再加载整集视角表。6,941字节的小索引指向34份配置，逐页原始字节SHA、原图与视频绑定均校验；第009与015源页SHA相同，仍按不同page.id和panel.id分开绑定。22项实际模块行为测试及34页真实配置加载测试通过，覆盖翻页取消、迟到响应、错误保留原画和当前页独立请求。

前后页原图预取已取消；原画优先显示，配置与环绕资源随后加载。16份保留脚本按既定顺序拼为一个公开阅读脚本。标题和背景首屏装饰资源共66,800字节，高清背景等当前页互动准备完后再取。装饰响应式副本涉及缩放及背景预览压缩，漫画原页与运动帧没有因此缩放或重编码。原背景音乐MP3保持原字节，实际网页播放使用完整AAC 96 kbps副本，约3.64 MB，时长298.008秒，moov在mdat前，便于渐进播放；浏览器自动播放限制仍适用。

单格加载百分比：每个非背景互动区域有一个独立的醒目百分比卡片，位于其源坐标矩形中央，独立于透明/裁剪播放器，不阻挡拖动。按真实已核验帧数计算；文字保护或首次解码尚未就绪时最多99%，完整就绪即隐藏，复位与拖动不复现。视频后备按真实已缓冲时长显示，经过现有解码、保护层、时长/尺寸和完整定位范围校验后隐藏。受控模块测试覆盖34页/50区域、不同格独立更新、完成隐藏、错误和翻页清理。

进一步加载优化：原图与当前页小配置并行，播放器仍需等待原图显示和配置校验。失败、取消及迟到响应不能启动旧页媒体。小配置和帧包请求带来源绑定的SHA查询参数，浏览器优先使用该精确内容的缓存；初始化、最终完成回调仍异步送达，其余进度更新合并到绘制帧，降低多格页面重复更新。所有帧包、静态原画、原视频、保护层及音乐文件在本次修改中保持原字节。

本轮单格提示与加载修复：提示改为各格中央的醒目卡片，显示「环绕画面加载中」、实际百分比与尚未完整就绪的解释；窄格使用紧凑排版，全部就绪后整张卡片隐藏。修复150、162、163帧序列初始邻帧没有覆盖全部分包、导致进度停在约75%的问题，所有分包均进入队列，各格首视角优先、相同优先级均衡下载。全部38组实际序列在无需拖动的受控传输测试中均能完成；保留4路下载/解码、24位图上限、逐帧/整包校验和翻页取消。

同时将运动缓存从保留JPEG重新编码为q76，全部6437帧的尺寸、顺序与媒体绑定保持一致；不是从有损q84再次转码。逐帧实际解码验证尺寸，代表性人物/细线画面已人工对比。原漫画页、分格原图、保护层、视频和音乐不改动。具体前后字节数及各格记录见frame-compression-v6.json；资源缩小比例不等同于实际网络等待时间的提升比例。以上新增测试与旧回归均在最终资源上重新执行，公开页面另验收。

后台下载中断也会更新进度状态，即使已核验帧数没有变化或页面绘制暂停。已能打开的角度保持可用；单格显示中断提示，页面显示「重新准备」。不会因后台分包失败自动下载视频或自动重试；用户显式选择视频后备或请求到失败角度时仍按既有规则处理。新增7项实际包数据/模块故障测试通过，包括共享消费者、迟到回调清理、保护现有可用视角和重试入口；单格提示20项、缓存43项、完整分包调度42项、页面加载25项、播放器21项回归均通过。


load7 进一步缩小首次互动前必须加载的文字/格框保护层：保留全部原 PNG，并优先加载逐像素一致的无损 WebP 副本。38 个原路径对应37个去重副本，总传输字节从17,025,179降为10,340,836（减少39.26%，仅指保护资源）。副本错误或尺寸不符会单次回退到原 PNG；保护未通过时继续显示原画。保护层使用高下载优先级，翻页清除过期图片请求。最近完整核验的压缩帧最多保留2组、合计16 MiB，返回这些画格无需重新下载或解析帧包；不保留解码位图，不预载邻页，不缓存未完成或失败的序列。资源节省不等同于浏览器等待时间的同比改善。

保护层 WebP 新增38组逐像素核对、7项资源映射测试与34项实际播放器受控测试通过，包括错误绑定拒绝、单次PNG回退、销毁和配对分区。最近帧缓存新增4项真实帧包测试通过，包括零请求重访、未完成下载丢弃、2组上限和16 MiB预算。首次冷加载不会获得已访问缓存的收益。线上发布、HTTP文件核对与浏览器检查应分开记录；本地检查不等同于公开网络速度保证。


load8 加入小体积环绕预览：每组从现有已核验高清帧按原索引均匀取24帧，最长边480、WebP q65，共912张预览、14,655,372字节，为完整高清帧包262,607,222字节的5.58%。预览是缩小/有损编码的临时画面，不是新增视角；完整高清帧和静态原画均保留。当前页各组预览优先，随后补齐高清；缺少目标高清时使用圆周最近的已核验预览，目标高清到达后直接替换，不把预览计入高清进度。原视角复位保留原漫画。预览阶段显示实际预览百分比，随后显示独立高清百分比及「预览可拖动，高清加载中」，全部高清与保护就绪才隐藏。8秒没有任何有效数据的预览会中止并放行高清，持续缓慢传输不受总时长限制。

大帧包另增加受信静态镜像；浏览器用两份16 KiB、长度与SHA均核验的小探针选择先完成的线路。镜像按完整SHA命名文件，维持长期缓存和no-transform；网络/HTTP错误可回源。流式正文已开始后的错误不会无感重拉当前包：现有提示保留，坏镜像在本次阅读禁用，后续请求或重新准备走原地址。手动翻页取消仍贯穿所有请求。源码与原GitHub阅读地址保留。线路短测与资源缩小比例不代表所有地区或浏览器的实际等待时间保证。

预览运行时新增78项、播放器/两阶段卡片8项、分发模块21项受控检查通过。离线工具还逐项核对38个预览包、912张预览的SHA、WebP尺寸、索引覆盖与原页/视频绑定；不把受控检查当作浏览器实测速。
