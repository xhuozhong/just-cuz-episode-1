# Just Cuz · 第一集：生日派对

[打开互动漫画](https://xhuozhong.github.io/just-cuz-episode-1/)

第一集共 34 页，对应原合集 PDF 第 2–35 页；合集首页不作为故事页。38 个主画格包含 50 个可独立操作的区域。

## 阅读方式

- 左右拖动画格查看其他方向，松开后缓慢减速；不同画格互不影响。
- 双击当前画格或按 Home 回到原画；“复位本页”还原整页。
- 使用翻页按钮或简洁目录换页。支持窄屏排版。
- 页头文字显示“正在准备”或“可以拖动”；其他角度尚未就绪时会继续准备，原画可以先读。
- 背景音乐会尝试自动播放；浏览器阻止有声自动播放时，首次点击页面后开始，可用音乐按钮暂停。

静态阅读与复位展示原漫画，保留原画文字和布局。其他视角根据原画补绘并生成视频，属于生成式环绕效果，部分片段存在视角衔接变化，不代表可自由移动的真实三维场景。

## 公开版本

网站内容位于 `dist/`，无需安装依赖或构建。GitHub Actions 将该目录发布到 GitHub Pages。可通过任意本地静态服务器预览。

6,437 张交互缓存帧使用 WebP 有损压缩，直接从保留的 JPEG 编码为 quality 76；个别原缓存更小时保留原缓存。保持全部帧数、顺序与尺寸，没有重绘、插帧或新增视角。每个画格按四组交错打包，共152个帧包。包内优先准备左右邻近视角；每帧独立核对长度与SHA-256后即可显示，不必等整包下载完成。各格首个视角优先，其他分包均会排队完成，不再依赖拖动触发。帧图与文字保护层就绪后即可拖动，MP4只在缓存不可用或播放视频时加载。原漫画页面、单格原图、视频、文字保护图层与音乐保留原文件。资源大小见 [压缩记录](docs/frame-compression-v6.json)，详细检查见 [验收说明](docs/acceptance.md)。

漫画、音乐及生成画面的相关权利归各自权利人。本仓库不对这些素材另授开源许可。播放器借鉴项目及字体的许可见 [第三方说明](dist/THIRD_PARTY_NOTICES.md)。

首屏资源按当前阅读页准备：仅载入约7 KB的页索引，进入一页时再下载该页配置；取消前后页原图预取，翻页取消旧页请求，已访问的小配置仅保留最近两页。公开页面合并为单个阅读脚本。标题使用适合显示尺寸的透明WebP，背景先显示小预览，当前页互动资源就绪后再补高清背景；节省流量模式保留小预览。背景音乐网页副本为完整AAC 96 kbps、可渐进播放，原MP3仍保留。

每格准备期间，在该画格中央显示「环绕画面加载中」和醒目的实际加载百分比；完整视角尚在加载时明确提示。全部画面及文字保护层就绪后整张提示自动隐藏，复位不重新显示，提示不阻挡拖动。后台角度下载中断时，单格明确显示中断提示，并显示页面「重新准备」入口；已打开的角度仍可查看。原图与当前页小配置并行准备，仍待原图显示后才创建环绕播放器。小配置与帧包通过内容SHA限定缓存地址，再次访问优先复用浏览器缓存；资源内容仍逐项校验。


load7 进一步缩小首次互动前必须加载的文字/格框保护层：保留全部原 PNG，并优先加载逐像素一致的无损 WebP 副本。38 个原路径对应37个去重副本，总传输字节从17,025,179降为10,340,836（减少39.26%，仅指保护资源）。副本错误或尺寸不符会单次回退到原 PNG；保护未通过时继续显示原画。保护层使用高下载优先级，翻页清除过期图片请求。最近完整核验的压缩帧最多保留2组、合计16 MiB，返回这些画格无需重新下载或解析帧包；不保留解码位图，不预载邻页，不缓存未完成或失败的序列。资源节省不等同于浏览器等待时间的同比改善。


load8 加入小体积环绕预览：每组从现有已核验高清帧按原索引均匀取24帧，最长边480、WebP q65，共912张预览、14,655,372字节，为完整高清帧包262,607,222字节的5.58%。预览是缩小/有损编码的临时画面，不是新增视角；完整高清帧和静态原画均保留。当前页各组预览优先，随后补齐高清；缺少目标高清时使用圆周最近的已核验预览，目标高清到达后直接替换，不把预览计入高清进度。原视角复位保留原漫画。预览阶段显示实际预览百分比，随后显示独立高清百分比及「预览可拖动，高清加载中」，全部高清与保护就绪才隐藏。8秒没有任何有效数据的预览会中止并放行高清，持续缓慢传输不受总时长限制。

大帧包另增加受信静态镜像；浏览器用两份16 KiB、长度与SHA均核验的小探针选择先完成的线路。镜像按完整SHA命名文件，维持长期缓存和no-transform；网络/HTTP错误可回源。流式正文已开始后的错误不会无感重拉当前包：现有提示保留，坏镜像在本次阅读禁用，后续请求或重新准备走原地址。手动翻页取消仍贯穿所有请求。源码与原GitHub阅读地址保留。线路短测与资源缩小比例不代表所有地区或浏览器的实际等待时间保证。
